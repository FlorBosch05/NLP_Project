# Qwen V3 evaluation

The separate experiment uses `qwen/qwen3.8-27b` without changing the app or `.env`. The source run `results/evaluation_qwen_sections_k5_20261125_135121.json` contains 20 cases, all routed as expected, with 14,771 reported model tokens across calls. In that first run all six conversion/scaling cases failed because Qwen returned missing values from the original combined argument schema.

The new `chef/agent_qwen_v1.py` uses separate required, nullable input schemas for scaling and conversion. A second run `results/evaluation_qwen_sections_k5_20261125_170144.json` retested the six cases: all six matched their expected tool results. The 13 retrieval answers in the first run are not affected by the tool-schema change, but these are still two separate test runs, not one rerun of all 20 cases using the corrected agent.

Ragas batches `results/ragas_batch_qwen_20261125_170212_659900.json` and `results/ragas_batch_qwen_20261125_180243_250500.json` score the 13 retrieval answers from the first V3 run with Qwen as judge. The second batch resumes the last two cases after an interruption. All 13 cases have all three scores; the summary is `results/ragas_summary_20261125_180407_381800.json`. Mean context precision is 0.9513, context recall 1.0000 and faithfulness 0.8949. These are estimated scores on a small synthetic set, not guarantees of accuracy. Judge usage was not instrumented, so 14,771 is the generation-run token count, not the total cost of the benchmark. Do not combine with V2 scores or scores from other judges. Using the same model for answers and judging risks bias. The synthetic dataset and references remain unverified by an independent reviewer.
